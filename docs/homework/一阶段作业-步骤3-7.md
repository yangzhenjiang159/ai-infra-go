## 批改（总评：50 分，及格边缘——结果表全对，但重头戏 3.3 全错）

### 作业 3.1：❌ 第三项答错 + 没答第二问

| 你的说法 | 判定 | 说明 |
|---|---|---|
| 模型权重、KV cache、**请求量** | ❌ | 第三项不是"请求量"。显存三部分 = **权重 + KV Cache + 激活值（Activations）**。激活值是前向计算过程的中间张量，独立占一份显存。"请求量/并发"不是显存占用项，而是放大 KV Cache 和激活值的**乘数** |
| （未回答"哪部分固定、哪部分随并发涨"） | ❌ | 这道题第二问漏答了。标准答案：**权重 = 固定成本**（由模型+精度决定）；**KV Cache = 可变成本**（随 序列长度×并发 线性上涨，OOM 主因）；**激活值 = 随 batch 大小变化** |

### 作业 3.2：✅ 结果全对，❌ 没写推导（题目明确要求）

数字全对（14G/140G、7G/70G、3.5G/35G），但作业要求"**务必手写推导过程**"，你只填了表。推导链条必须写出来才算过关：

```
权重(字节) = 参数量 × 每参数字节数
7B FP16 = 7×10⁹ × 2 B = 14×10⁹ B ≈ 14 GB
70B FP16 = 70×10⁹ × 2 B = 140 GB
FP8 字节减半 → 7GB / 70GB；FP4 再减半 → 3.5GB / 35GB
```

### 作业 3.3：❌ 全错（这是本步核心，必须重写）

你的算式 `28 × 2 × 3584 × 0.4Mb × 4k + 14G` 有三个致命问题：

| 问题 | 说明 |
|---|---|
| **重复计算** | `0.4MB` 本身就是 `28 × 2 × 3584 × 2B` 算出来的"每 token"结果，你又乘了一次 `28×2×3584` = 把层数和 hidden 维度算了**两遍** |
| **混入权重** | 题目问的是"KV Cache 占多少"，你 `+ 14G` 把权重加了进来——**KV Cache 的账和权重的账要分开算** |
| **单位混乱** | `0.4Mb` / `0.0004GB` / `0.00000381GB` 三个数字混用，`0.00000381` 来历不明 |

正确解法（一条公式链，不要再乘层数）：

```
每 token 的 KV Cache = 28层 × 2(K和V) × 3584(hidden) × 2字节 ≈ 0.4 MB

① 一条 4K 请求  = 0.4MB × 4096 ≈ 1.6 GB     ← 单请求就 1.6G
② 并发 10 条    = 1.6GB × 10 = 16 GB        ← 只算 KV Cache 已 16G
③ FP8 精度      = 每 token 减半 ≈ 0.2MB      ← K/V 也是按字节存的
                 一条 4K ≈ 0.8GB，并发 10 ≈ 8GB
```

结论要说出来：**12G 卡上权重 + KV Cache 加起来必然 OOM，而且 KV Cache 的 16G 已经单独超过整卡显存**——这就是"OOM 几乎都是 KV Cache 撑的，不是权重"这句话的数字来源。

### 作业 3.4：⚠️ 第 1 题方向对但答不完整，第 2 题 ✅

| 你的说法 | 判定 | 说明 |
|---|---|---|
| 3B 权重 6G、7B 权重 14G | ⚠️ | 方向对（14G > 12G），但漏了关键一层：**12G 是总显存，实际可用要减框架开销 1-2GB 和激活/预留，约剩 10-11G**。7B 权重 14G 单权重就超整卡；3B 权重 6G，剩约 4-5G 还能分给 KV Cache。所以"12G 只能跑 3B"的完整答案是这两步 |
| 14G/7G/3.5G | ✅ | 对 |
