# AI Infra 转型路线图 · 全项目专业名词速查表

> 用法：本文档把 `ai-infra-12month-roadmap.md` 及四份阶段手册、一阶段作业里出现的**所有专业名词**按类目罗列。
> 每条给出一句话定位、**优先级**、**建议学习时机**（S1-S4 = 阶段一至阶段四，HW = 一阶段作业）以及**资料在哪**。

## 优先级与时机约定

| 标记 | 含义 | 掌握程度要求 |
|---|---|---|
| **P0** | 必须吃透，面试会被深挖 | 能脱稿讲 60 秒 + 能动手验证 |
| **P1** | 重要 | 能讲清关键点、会用对应配置/命令 |
| **P2** | 了解即可 | 知道"是什么、解决什么问题"，一句话定位 |

> 资料入口约定：`S1 §四` 表示《stage1…详细步骤》第 4 节；`roadmap §3.1` 表示总路线图第 3.1 节。
> `官档` = 官方文档；`arXiv:xxx` = 论文编号；完整链接汇总见文末《附录：权威资料总入口》。

## 0. 学习总览（先看这张图）

```
阶段一 S1  推理基础 + 两个引擎（vLLM/SGLang）—— 名词最密集，P0 占多数
```

## A. LLM 推理基础（S1，最底层的心法）

| 术语 | 一句话讲清 | 优先级·时机 | 资料在哪 |
|---|---|---|---|
| Transformer | 大模型的底层架构（注意力 + 多层网络），Tokenizer 只是它的外围 | **P0**·S1 | `S1 §三`；`arXiv:1706.03762`；3Blue1Brown 视频 |
| Token（分词） | 文本被切开的最小单元，先分词再向量化才能进 Transformer | **P0**·S1 | `S1 §三`；`HW`；HF 文档 Tokenizer |
| Q/K/V | 注意力三件套：**Q 用完即弃，只有 K/V 存进 KV Cache** | **P0**·S1 | `HW 批改`（重点纠偏） |
| 自回归生成 | 每步只预测下一个 token，输出拼回输入再走下一步 | **P0**·S1 | `HW`；`S1 §三` |
| 词表 / Softmax | 模型输出的概率分布落在整个词表上（一次 Softmax），选最高者 | P1·S1 | `HW 批改` |
| Prefill（预填充） | 一次性并行算完 prompt 所有 token 的 K/V → **计算密集** | **P0**·S1 | `S1 §三`；`HW` |
| Decode（解码） | 逐 token 自回归，每步只读 KV Cache 算 1 个 token → **访存密集** | **P0**·S1 | `S1 §三`；`HW` |
| PD 分离（Disaggregated Prefill/Decode） | 把"吃算力的 prefill"和"吃带宽的 decode"拆到两拨 GPU，防互相踩踏；代价是 KV 跨机传输 | **P0**·S1/S4 | `S1 §三`；`S4 §三`；vLLM 官档 Disagg Prefill |
| KV Cache | 存放历史 K/V 的缓存，大小随 序列长度×并发 线性上涨，是 OOM 主因 | **P0**·S1 | `S1 §四`；腾讯云 KV Cache 文章（`S1 §十`） |
| 权重（Weights） | 模型参数本身，固定成本，= 参数量 × 每参数字节 | **P0**·S1 | `S1 §4.2`（表格可推导） |
| 激活值（Activations） | 前向计算的中间张量，随 batch 大小变化 | **P0**·S1 | `S1 §4.1` |
| 显存三部分 | 显存 = 权重 + KV Cache + 激活值 | **P0**·S1 | `S1 §4.1` |
| 参数量（7B/70B/671B） | 模型规模单位：7B ≈ 70 亿参数 | **P0**·S1 | `S1 §4.2`；HuggingFace |
| 隐藏维度（hidden_size） | 显存公式里的关键因子：层数×2×序列长度×hidden×字节 | **P0**·S1 | `S1 §4.3`；`HW` 以 Qwen2.5-7B 演示 |
| 层数 | Transformer 堆叠层数（如 Qwen2.5-7B = 28 层） | **P0**·S1 | `HW` |
| 序列长度（上下文长度） | 一条请求的 token 数，直接放大 KV Cache | **P0**·S1 | `S1 §4.3` |
| MoE（混合专家） | DeepSeek 类架构：总参数 671B 但每 token 只激活 ~37B，省算力不省显存 | **P0**·S4 | `S4 §二`；`roadmap §3.1`；MoE 知乎文（`S4 §七`） |

## B. 显存管理与注意力优化（S1/S2/S4）

| 术语 | 一句话讲清 | 优先级·时机 | 资料在哪 |
|---|---|---|---|
| 显存碎片化 | 为最长序列预留连续显存导致的浪费 + 请求长短不一产生的碎片 | **P0**·S1 | `S1 §5.1` |
| PagedAttention | vLLM 立身之本：把 KV Cache 切成固定块按需分配（类比 OS 内存分页），消除碎片、提吞吐 | **P0**·S1 | `S1 §5`；`arXiv:2309.06180` |
| RadixAttention | SGLang 的前缀缓存：分页 + 基数树前缀复用，跨请求共享相同前缀 KV | **P0**·S1 | `S1 §5.3`；`arXiv:2312.07104` |
| 前缀缓存（Prefix Caching / APC） | 相同 system prompt 前缀的 KV 直接复用，免重复计算，可省 50%+ | P1·S1/S2 | `roadmap §2.1/3.1`；vLLM 官档 Automatic Prefix Caching |
| FlashAttention | IO 感知注意力：分块 + 重计算换显存访问，S4 论文精读 | P1·S4 | `arXiv:2205.14135`；`S4 §四` |

| OOM | 显存耗尽；推理 OOM 几乎都是 KV Cache 撑爆而非权重装不下 | **P0**·S1 | `S1 §七`；`HW` 显存账 |
| max-num-seqs | vLLM 参数：限制同时在跑请求数（KV Cache 占用上限的关键旋钮） | **P0**·S1 | `S1 §六`；`roadmap §2.5` |
| gpu-memory-utilization | vLLM 参数：给权重/KV Cache 预留的显存比例，调爆它=体验 OOM | **P0**·S1 | `S1 §七`；vLLM 官档 |
| mem-fraction-static | SGLang 对应参数（静态显存占用比例） | P2·S1 | `S1 §6.2` |

## D. 调度与推理优化（S2 为主）

| 术语 | 一句话讲清 | 优先级·时机 | 资料在哪 |
|---|---|---|---|
| 静态 Batching | 早期方式：凑满一批才跑，短请求等长请求，GPU 空转 | P1·S2 | `S2 Part B`；Orca 论文对比 |
| Continuous Batching（连续批处理） | 每步 decode 后动态插拔请求（Orca 的 iteration-level 调度），吞吐大幅提升 | **P0**·S1/S2 | `S2 Part B`；`roadmap §3.1`；腾讯云文（`S2 §八`） |
| Chunked Prefill（分块预填充） | 把长 prompt 的 prefill 切成块混进 decode，防止长 prompt 卡死同批短请求 | P1·S2 | `S2 Part B`；`S2 §八` 腾讯云文 |
| Speculative Decoding（投机解码） | 小模型 draft 猜 N 个 token，大模型并行 verify，接受率决定收益 | P1·S2（了解级） | NVIDIA 博文 + 腾讯云文（`S2 §八`） |
| EAGLE-3 | 投机解码的进阶（在特征层 draft，非词表层） | P2·S2 | `roadmap §3.1`；搜索 EAGLE-3 |
| 拒绝采样（rejection sampling） | 保证投机解码输出分布与原模型一致 | P2·S2 | NVIDIA 投机解码博文 |
| 三层缓存体系 | 前缀缓存（引擎内）/ KV 复用（引擎内，多租户语义对齐）/ 语义缓存（网关层） | **P0**·S2 | `roadmap §3.1`；`S2 Part C` |
| 语义缓存 | 请求→embedding→向量库余弦检索，相似度超阈值直接返回缓存 | P1·S2 | `S2 Part C`（重点实现） |
| KV 复用 / 语义对齐 | 多租户/灰度/A-B 场景复用 KV 时的错位风险，需 tenant_id、schema_version 维度编码 | P1·S2 | `S2 Part C`；`roadmap §3.1` |
| 向量化 / embedding | 把文本映射成向量，是语义缓存与检索的前提 | **P0**·S2 | `S2 v2.0`；`roadmap §3.1` |
| 余弦相似度 | 向量相似度度量，语义缓存命中判断（如 >0.95） | P1·S2 | `S2 v2.0` |
| 向量数据库 | 存向量做相似检索：Qdrant（主用）、Milvus（可选加分项） | P1·S2 / P2·S4 | qdrant.tech；`S2 v2.0`；`roadmap §五` |
| HNSW | 向量库底层索引算法（跳表+贪心搜索），S4 可选项 | P2·S4 | `roadmap §5.1`；`S4 Part C 可选项` |
